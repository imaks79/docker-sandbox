# docker-tasker

Скрипт для быстрого разворачивания docker-контейнера "для экспериментов":
поднять образ, зайти внутрь shell'ом, погонять скрипты, при необходимости
пробросить порт или сохранить доустановленные пакеты.

## Требования

- Установленный и запущенный Docker (Docker Desktop на macOS/Windows или
  `dockerd` на Linux).

## Быстрый старт

```bash
./sandbox.sh
```

Поднимет контейнер `sandbox` на образе `ubuntu:latest` и сразу подключит
вас интерактивным bash. Файлы в `./workspace` на хосте видны внутри
контейнера как `/workspace`, и наоборот.

Повторный запуск той же команды не создаёт новый контейнер — если он уже
существует и запущен, вы просто подключитесь к нему; если остановлен —
скрипт его запустит.

## Использование

```
./sandbox.sh [опции] [образ] [имя]
./sandbox.sh stop    [имя]
./sandbox.sh rm      [имя]
./sandbox.sh logs    [имя]
./sandbox.sh rebuild [имя]
```

По умолчанию `образ` = `ubuntu:latest`, `имя` = `sandbox`.

### Опции (действуют только при СОЗДАНИИ контейнера)

| Опция | Что делает | Пример |
|---|---|---|
| `-p HOST:CONTAINER` | Проброс порта, можно указывать несколько раз | `-p 8080:80` |
| `-m LIMIT` | Лимит памяти | `-m 512m`, `-m 1g` |
| `-c LIMIT` | Лимит CPU | `-c 1.5` |
| `-u` | Запускать процессы от текущего пользователя хоста, а не root | `-u` |

Если контейнер с таким именем уже существует, эти опции игнорируются —
скрипт предупредит и подскажет сначала выполнить `./sandbox.sh rm <имя>`.

### Примеры

```bash
# Ubuntu-песочница по умолчанию
./sandbox.sh

# Свой образ и своё имя контейнера — можно держать несколько независимых
# песочниц параллельно, просто давая им разные имена
./sandbox.sh python:3.12-slim py
./sandbox.sh node:20-slim node-sbx

# Тестируем веб-сервер: пробрасываем порт 8080 хоста на 80 контейнера
./sandbox.sh -p 8080:80 nginx web

# Ограничиваем ресурсы и пишем файлы от своего пользователя, а не root
./sandbox.sh -m 512m -c 1 -u ubuntu:latest sandbox

# Посмотреть логи фоновых процессов в контейнере
./sandbox.sh logs sandbox

# Остановить / удалить
./sandbox.sh stop sandbox
./sandbox.sh rm sandbox
```

## Папка workspace

`./workspace` монтируется в `/workspace` внутри контейнера и является
рабочей директорией по умолчанию. Пишите скрипты в любимом редакторе на
хосте — они сразу доступны в контейнере, и наоборот. В git-репозитории
содержимое папки игнорируется (см. `.gitignore`), сама папка сохраняется
через `.gitkeep`.

## Сохранение окружения через Dockerfile

Обычный запуск использует "чистый" образ — всё, что вы доустановите
внутри контейнера (`apt install ...`), потеряется при `./sandbox.sh rm`.
Чтобы этого избежать:

1. Скопируйте `Dockerfile.example` в `Dockerfile` и допишите нужные пакеты.
2. Запустите `./sandbox.sh rebuild` — соберётся образ `sandbox-image:<имя>`.
3. Дальнейшие `./sandbox.sh` будут использовать этот собранный образ
   вместо `ubuntu:latest`, даже без явного указания образа.

Если `Dockerfile` в проекте нет, скрипт работает как обычно — тянет
образ по имени из аргумента.

## Про non-root режим (`-u`)

По умолчанию процессы в контейнере выполняются от root — это удобно,
если нужно ставить пакеты (`apt install`) прямо в рантайме. Но тогда
файлы, которые процесс создаёт в `/workspace`, на хосте будут
принадлежать `root`, и их неудобно потом удалять/редактировать под
обычным пользователем.

Флаг `-u` запускает процессы от вашего текущего UID/GID — файлы в
`workspace` будут с правильным владельцем. Обратная сторона: внутри
контейнера не будет прав на `apt install` и на запись вне `/workspace`.
Используйте `-u`, когда просто гоняете скрипты и не нужно ничего
доустанавливать в рантайме.

## Известные ограничения

- Контейнер без `Dockerfile` не сохраняет доустановленные пакеты между
  пересозданиями — см. раздел про Dockerfile выше.
- Одно имя контейнера = одно окружение; для нескольких параллельных
  песочниц используйте разные `имя`.
- Порты/лимиты ресурсов фиксируются при создании контейнера; чтобы
  поменять их, нужно `./sandbox.sh rm <имя>` и создать заново.
- Скрипт рассчитан на bash-совместимую оболочку (macOS/Linux); на
  Windows нужен WSL или Git Bash.
