# Идеи для учебной лаборатории

Этот репозиторий — песочница для практики с Docker и Linux: разворачивать
контейнеры, ломать и чинить, пробовать новое без риска для рабочей
машины. `sandbox.sh` даёт быстрый цикл "поднял → потрогал → снёс", а
`templates/` — готовые и учебные сценарии для конкретных тем (по
образцу `samba-manual` / `samba-ready`, см. [README.md](README.md)).

Ниже — темы, которые можно развить в этом же формате: по шаблону
"manual" (тренировка руками + `TUTORIAL.md`) и/или "ready" (готовый
рабочий контейнер + `README.md`).

## Обмен файлами и сетевые сервисы

- **FTP/SFTP-сервер** (vsftpd или OpenSSH SFTP) — альтернатива Samba,
  разница в протоколах и авторизации.
- **NFS-шара** — сравнить с Samba: как выглядит "шара" в мире Unix/Unix,
  разница в модели прав доступа.
- **WebDAV** (через Apache/nginx) — шара файлов поверх HTTP.
- **Простой HTTP file server** (`python3 -m http.server`, `dufs`,
  `miniserve`) — самый быстрый способ "отдать" папку, без авторизации.
- ✅ **rsync daemon** — синхронизация файлов между машинами, инкрементальные
  бэкапы. Реализовано: [`templates/rsync-daemon`](templates/rsync-daemon/README.md).
- ✅ **Syncthing** — постоянная двусторонняя синхронизация между несколькими
  контейнерами/хостами. Реализовано: [`templates/syncthing`](templates/syncthing/README.md).

## Веб и прокси

- **nginx как reverse proxy** перед несколькими контейнерами — маршрутизация
  по домену/пути, `docker network`.
- **HTTPS для локальной сети** — самоподписанные сертификаты (`mkcert`)
  или `step-ca` как собственный локальный CA.
- **Load balancer** (HAProxy/nginx) — балансировка между несколькими
  копиями одного сервиса, health checks.
- **Статический сайт-хостинг** — nginx/Caddy, автоматический TLS через
  Caddy как отдельная тема.

## Базы данных и хранилища

- **PostgreSQL/MySQL с именованным томом** — персистентность данных
  между пересозданиями контейнера, бэкап/восстановление через `pg_dump`.
- **Redis** — кэш и pub/sub, посмотреть на persistence (RDB/AOF).
- **MinIO** — S3-совместимое хранилище локально, потренироваться с S3 API.

## Сети и многосервисные стенды

- **docker-compose стенд из нескольких сервисов** (например, nginx +
  приложение + БД) — знакомство с `docker-compose.yml`, зависимостями
  между сервисами, общими сетями.
- **Собственная Docker-сеть** (`docker network create`) — как контейнеры
  видят друг друга по имени, разница bridge/host/none.
- **DNS-сервер** (dnsmasq/bind9) — локальное разрешение имён для стенда.
- ✅ **VPN/WireGuard-сервер** — поднять туннель между хостом и контейнером.
  Реализовано: [`templates/wireguard-ready`](templates/wireguard-ready/README.md)
  (нужен флаг `-n`, см. README).

## Инфраструктура и автоматизация

- **CI-раннер** (например, простой self-hosted GitHub Actions runner
  или Gitea + CI) — запуск пайплайнов локально.
- **Git-сервер** (Gitea/Gogs) — свой git hosting в локальной сети.
- **Ansible playground** — контейнер как "управляемый хост" для
  тренировки Ansible-плейбуков без реальных серверов.
- ✅ **Cron/systemd-timer в контейнере** — периодические задачи, разница
  между PID 1 без init-системы и полноценным systemd-контейнером.
  Реализовано: [`templates/systemd-timer`](templates/systemd-timer/TUTORIAL.md)
  (нужен флаг `-i`, см. TUTORIAL — там же и сравнение с cron в обычной
  песочнице без init-системы).
- **Vault/секреты** — HashiCorp Vault или Docker secrets, хранение и
  выдача чувствительных данных.

## Мониторинг и логирование

- **Prometheus + Grafana** — метрики контейнеров, дашборды.
- **ELK/EFK stack** (Elasticsearch/OpenSearch + Fluent Bit/Logstash +
  Kibana) — агрегация логов с нескольких контейнеров.
- **docker stats / cAdvisor** — что показывают лимиты `-m`/`-c` из
  `sandbox.sh` изнутри контейнера, как выглядит OOM-kill при превышении.

## Безопасность

- **Непривилегированный контейнер** — `--user`, `--read-only`,
  `--cap-drop=ALL`, сравнить, что перестаёт работать и почему.
- **Сканирование образа на уязвимости** (`docker scout`, `trivy`).
- ✅ **Сеть с firewall внутри контейнера** (`iptables`/`nftables`) —
  фильтрация трафика между сервисами. Реализовано:
  [`templates/firewall-lab`](templates/firewall-lab/TUTORIAL.md)
  (нужен флаг `-n`, см. TUTORIAL).
- **Секреты и `.env`** — почему не стоит класть пароли в `ENV`
  Dockerfile, `docker secret` как альтернатива.

## Сборка образов

- **Multi-stage build** — уменьшение размера итогового образа
  (например, компиляция в одном слое, рантайм в другом).
- **Разница `CMD` vs `ENTRYPOINT`** — уже используется в
  `templates/samba-ready` (см. `entrypoint.sh`), можно оформить как
  отдельный обучающий пример с наглядными экспериментами.
- **Слои и кэш сборки** — как порядок инструкций в Dockerfile влияет на
  скорость пересборки, `docker history`.
- **Alpine vs Debian/Ubuntu базовые образы** — компромиссы в размере,
  совместимости, инструментах отладки.

## Формат для новых шаблонов

Каждая новая тема — это подпапка в `templates/<имя>/` по одной из двух
схем (см. уже готовые `samba-manual` и `samba-ready` как образец):

- **manual** — минимальный `Dockerfile` (голая ОС) + `TUTORIAL.md` с
  пошаговыми командами, чтобы настраивать руками и разобраться, как
  сервис устроен изнутри.
- **ready** — `Dockerfile`, который сразу собирает рабочий сервис
  (обычно через `ENTRYPOINT`-скрипт, поднимающий демоны в фоне и затем
  делающий `exec "$@"`, чтобы не конфликтовать с тем, как `sandbox.sh`
  держит контейнер живым через `sleep infinity`) + `README.md` с
  инструкцией по быстрому запуску.

Разворачивается это всё одинаково:
`./sandbox.sh -t <имя-шаблона> [опции] [имя-контейнера]`
(список — `./sandbox.sh templates`).
