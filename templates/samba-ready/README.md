# samba-ready — быстрая Samba-шара

Готовый к работе контейнер: собрали образ — Samba уже настроена и
запускается автоматически. Для случаев "хочу по-быстрому поделиться
файлами в локальной сети", без ручной настройки.

Шарится папка `/workspace`, то есть `./workspace` на хосте (тот же
маунт, что и во всех остальных песочницах `sandbox.sh`) — просто
положите файлы в `./workspace`, и они сразу появятся в шаре.

Хотите потренироваться настраивать то же самое руками, шаг за шагом —
см. [`templates/samba-manual`](../samba-manual/TUTORIAL.md).

## Быстрый старт

```bash
./sandbox.sh -s -t samba-ready share
```

- `-t samba-ready` — использовать этот шаблон.
- `-s` — пробросить порты Samba наружу (обязательно, иначе шара будет
  доступна только изнутри контейнера).
- `share` — имя контейнера (можно любое).

При первом запуске увидите в выводе логин и пароль по умолчанию, дальше
подключайтесь:

- **macOS**: Finder → `Cmd+K` → `smb://localhost:1445/workspace`
- **Linux**: `smbclient -p 1445 -L localhost -U sandbox` (пароль `sandbox`)
- **Windows**: `\\localhost@1445\workspace` в проводнике

(445-й порт хоста занят macOS системным File Sharing и недоступен
сторонним процессам, поэтому `sandbox.sh -s` публикует его на 1445 —
см. `./sandbox.sh -h`.)

## Логин и пароль по умолчанию

| Переменная | Значение по умолчанию |
|---|---|
| `SAMBA_USER` | `sandbox` |
| `SAMBA_PASSWORD` | `sandbox` |
| `SAMBA_SHARE_PATH` | `/workspace` |

Обязательно смените пароль перед тем, как пускать в шару кого-то ещё,
кому вы не доверяете локальную сеть, — по умолчанию это учебные
значения "из коробки", а не секрет.

Чтобы задать свои значения, поправьте `ENV` в
[`Dockerfile`](Dockerfile) и пересоберите образ:

```bash
./sandbox.sh -t samba-ready rebuild share
./sandbox.sh rm share
./sandbox.sh -s -t samba-ready share
```

## Как это устроено

- `Dockerfile` ставит `samba`/`samba-common-bin` и копирует
  `smb.conf.template` + `entrypoint.sh`.
- `entrypoint.sh` при каждом старте контейнера: подставляет
  `SAMBA_USER`/`SAMBA_SHARE_PATH` в конфиг, создаёт (если нужно)
  системного пользователя и Samba-пароль, поднимает `smbd`/`nmbd` в
  фоне, затем передаёт управление дальше (`sleep infinity` от
  `sandbox.sh`, чтобы контейнер не завершался).
- Всё идемпотентно — можно смело `./sandbox.sh stop share` /
  `./sandbox.sh share`, Samba поднимется заново с теми же настройками.

## Диагностика

- Логи: `./sandbox.sh logs share` покажет вывод контейнера; логи самой
  Samba — внутри контейнера, `/var/log/samba/log.smbd`.
- "`Connection refused`" снаружи — проверьте, что контейнер создавали с
  `-s` (опции действуют только при создании, см. `./sandbox.sh -h`).
- "`Access denied`" — неверный логин/пароль, либо `SAMBA_USER` был
  изменён после первого запуска (пересоберите и пересоздайте контейнер,
  см. выше).
