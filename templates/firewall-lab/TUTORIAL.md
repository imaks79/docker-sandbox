# Тренировка: firewall внутри контейнера (nftables/iptables)

Идея: внутри одного контейнера поднимаем два учебных "сервиса" на разных
портах — "публичный" (8001) и "административный" (8002, как будто там
что-то чувствительное вроде админки БД) — и настраиваем правила firewall
так, чтобы административный порт был доступен только с localhost, а
публичный был открыт всем. Так на практике видно, что значит "фильтрация
трафика между сервисами".

## Шаг 0. Поднять контейнер

```bash
./sandbox.sh -n -t firewall-lab fw
```

Флаг `-n` обязателен: без него `nft`/`iptables` внутри контейнера
упадут с `Operation not permitted` — Docker по умолчанию не даёт
контейнеру capability `NET_ADMIN`/`NET_RAW`, нужные для правки правил
маршрутизации и фильтрации.

## Шаг 1. Поднять два учебных "сервиса"

```bash
mkdir -p /tmp/public /tmp/admin
echo "я публичный сервис"       > /tmp/public/index.html
echo "я админка, секретная"     > /tmp/admin/index.html

(cd /tmp/public && python3 -m http.server 8001 &>/tmp/public.log &)
(cd /tmp/admin  && python3 -m http.server 8002 &>/tmp/admin.log &)

sleep 1
curl -s localhost:8001
curl -s localhost:8002
```

Оба ответят — по умолчанию внутри контейнера ничего не фильтруется,
любой процесс видит любой порт.

## Шаг 2. Посмотреть текущие правила

```bash
nft list ruleset
# или
iptables -L -n -v
```

Скорее всего пусто — фильтрации ещё нет.

## Шаг 3. Написать правила на nftables

Создаём таблицу и цепочку с политикой `drop` по умолчанию для входящих —
и затем явно разрешаем то, что нужно:

```bash
nft add table inet fw
nft add chain inet fw input '{ type filter hook input priority 0; policy drop; }'

# Разрешить уже установленные/связанные соединения (иначе даже ответы
# на собственные исходящие запросы будут дропаться)
nft add rule inet fw input ct state established,related accept

# Разрешить loopback (127.0.0.1) полностью — им ходят сами процессы
# друг к другу, а также ваш собственный curl изнутри контейнера
nft add rule inet fw input iif lo accept

# Публичный порт 8001 — разрешить всем
nft add rule inet fw input tcp dport 8001 accept

# Админ-порт 8002 — НЕ разрешаем отдельным правилом: он останется
# заблокирован политикой drop для всех, кроме loopback (уже разрешён
# правилом выше)
```

Проверьте итоговый набор правил:

```bash
nft list ruleset
```

## Шаг 4. Проверить результат

Изнутри контейнера (идёт через loopback — должно работать оба):

```bash
curl -s localhost:8001   # публичный — ок
curl -s localhost:8002   # админский — тоже ок, мы на loopback
```

С хоста (если пробросили порты — см. ниже) — публичный должен отвечать,
админский быть недоступен:

```bash
./sandbox.sh rm fw
./sandbox.sh -n -p 8001:8001 -p 8002:8002 -t firewall-lab fw
# повторите шаги 1 и 3 внутри контейнера, затем с хоста:
curl -s localhost:8001   # ок, публичный
curl -s localhost:8002   # не отвечает — заблокирован firewall'ом контейнера
```

## Шаг 5. Логировать заблокированные пакеты (опционально)

Полезно видеть, что именно дропается:

```bash
nft insert rule inet fw input log prefix "dropped: " counter drop
```

(добавит логирование прямо перед finальным drop policy; смотреть можно
через `dmesg` — в контейнере может быть недоступно без привилегий хоста,
поэтому это скорее для отсылки к тому, как это работает на реальном
сервере).

## Шаг 6. Сбросить правила

```bash
nft flush ruleset
```

Все правила исчезают, фильтрация выключена — снова оба порта доступны
отовсюду.

## То же самое через iptables (для сравнения)

nftables — современная замена iptables, но много инструкций в интернете
всё ещё написаны под старый синтаксис. Тот же результат (запрет всего
входящего кроме loopback, established/related и порта 8001):

```bash
iptables -P INPUT DROP
iptables -A INPUT -i lo -j ACCEPT
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A INPUT -p tcp --dport 8001 -j ACCEPT

iptables -L -n -v      # посмотреть правила
iptables -F            # сбросить (но не саму policy DROP!)
iptables -P INPUT ACCEPT   # вернуть политику в ACCEPT, иначе после -F
                            # весь входящий трафик останется заблокирован
```

Важно: `iptables -F` сбрасывает только сами правила, но НЕ default
policy — если забыли вернуть `-P INPUT ACCEPT`, контейнер останется
недоступен даже с пустым набором правил.

## Что дальше и о чём подумать

- В реальной сети firewall обычно стоит не "внутри" каждого сервиса, а
  на шлюзе/хосте, фильтруя трафик между несколькими контейнерами в
  одной docker-сети (`docker network create`, затем `iptables`/`nftables`
  на хосте или в отдельном контейнере-шлюзе с ролью роутера).
- Docker сам активно использует iptables на хосте для проброса портов
  (`-p`) и изоляции сетей — то, что мы делали здесь, было ВНУТРИ netns
  контейнера, отдельно и независимо от хостовых правил Docker.
- Попробуйте усложнить: разрешить 8002 только с конкретного IP через
  `nft add rule inet fw input ip saddr 10.0.0.5 tcp dport 8002 accept`.
