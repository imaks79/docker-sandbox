# syncthing — постоянная синхронизация файлов

Готовый к работе Syncthing: собрали образ — Web UI и сама синхронизация
сразу доступны. В отличие от Samba/rsync (разовый или "по требованию"
доступ), Syncthing держит соединение с другими узлами и синхронизирует
файлы непрерывно, в обе стороны.

## Быстрый старт

```bash
./sandbox.sh -p 8384:8384 -p 22000:22000 -p 22000:22000/udp -p 21027:21027/udp -t syncthing sync
```

- `8384` — Web UI.
- `22000` (tcp+udp) — протокол синхронизации между узлами.
- `21027/udp` — автообнаружение узлов в локальной сети.

Откройте `http://localhost:8384` — логин/пароль по умолчанию
`sandbox`/`sandbox` (см. переменные ниже).

## Синхронизация с другим устройством

1. В Web UI откройте **Actions → Show ID**, скопируйте Device ID (он же
   печатается в лог при старте контейнера, `./sandbox.sh logs sync`).
2. На втором устройстве (обычный Syncthing на хосте, телефоне, или
   второй такой же контейнер — см. ниже) добавьте это устройство по
   Device ID через **Add Remote Device**.
3. После взаимного подтверждения на обеих сторонах — поделитесь папкой
   (по умолчанию ничего не расшарено, добавьте её сами: **Add Folder**,
   путь `/workspace`, либо создайте свою подпапку).
4. Файлы, положенные в `./workspace` на любой из сторон, появятся на
   другой автоматически.

### Два контейнера друг с другом (демонстрация на одной машине)

```bash
./sandbox.sh -p 8384:8384   -p 22000:22000   -p 22000:22000/udp -p 21027:21027/udp -t syncthing node-a
./sandbox.sh -p 8385:8384   -p 22001:22000   -p 22001:22000/udp -p 21028:21027/udp -t syncthing node-b
```

Оба поднимутся на своих портах (`node-a` — 8384, `node-b` — 8385).
Зайдите в оба Web UI, обменяйтесь Device ID, добавьте папку на одном —
подтвердите приглашение на другом. Дальше файлы, попавшие в
`./workspace` любого из контейнеров (это разные папки на хосте, так как
у контейнеров разные имена — `docker inspect node-a` покажет реальный
путь), синхронизируются между ними через локальную сеть/loopback.

## Переменные окружения

| Переменная | По умолчанию | Что это |
|---|---|---|
| `ST_HOME` | `/workspace/.syncthing` | где хранится конфиг/ключи (внутри `/workspace`, чтобы Device ID переживал пересоздание контейнера) |
| `ST_GUI_USER` | `sandbox` | логин Web UI |
| `ST_GUI_PASSWORD` | `sandbox` | пароль Web UI |

Чтобы поменять — поправьте `ENV` в [`Dockerfile`](Dockerfile) и
пересоберите (учтите: смена логина/пароля не влияет на уже
сгенерированный `config.xml`, для применения удалите
`./workspace/.syncthing` перед пересозданием контейнера, иначе старые
ключи и Device ID просто продолжат использоваться):

```bash
./sandbox.sh -t syncthing rebuild sync
./sandbox.sh rm sync
./sandbox.sh -p 8384:8384 -p 22000:22000 -p 22000:22000/udp -p 21027:21027/udp -t syncthing sync
```

## Как это устроено

- При первом старте `entrypoint.sh` вызывает `syncthing generate`,
  который создаёт `config.xml`, ключи устройства и прописывает
  GUI-логин/пароль — без запуска самого демона.
- Дальше поднимается `syncthing serve` в фоне, и управление передаётся
  `exec "$@"` (`sleep infinity` от `sandbox.sh`).
- Конфиг лежит в `/workspace/.syncthing`, то есть виден на хосте как
  `./workspace/.syncthing` — Device ID и ключи переживают
  `docker stop`/`docker start` и даже `docker rm`, пока цела эта папка
  на хосте.

## Диагностика

- Web UI недоступен снаружи — проверьте, что контейнер создавали с
  `-p 8384:8384`; опции применяются только при создании.
- Узлы не видят друг друга по автообнаружению — проверьте проброс
  `21027/udp`; либо добавьте адрес вручную вместо автообнаружения
  (в настройках удалённого устройства — Addresses: `tcp://<host>:22000`).
- Забыли Device ID — `docker exec sync cat /workspace/.syncthing/device-id.txt`
  либо смотрите Web UI: **Actions → Show ID**.
