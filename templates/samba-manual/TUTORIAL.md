# Тренировка: разворачиваем Samba-шару вручную

Этот шаблон — "чистая" Ubuntu без Samba. Идея: вы как будто только что
получили сервер (физический, VPS, или вот эту песочницу) и хотите
поделиться папкой по сети из-под Ubuntu/Linux с нуля, без готовых
скриптов. Все команды ниже выполняются **внутри контейнера**, от root.

## Шаг 0. Поднять контейнер

С хоста, из папки `docker-sandbox`:

```bash
./sandbox.sh -s -t samba-manual samba-training
```

`-s` пробрасывает наружу порты Samba (445/139/137/138), `-t samba-manual`
берёт именно этот шаблон. Вы окажетесь внутри контейнера shell'ом,
рабочая папка — `/workspace` (это `./workspace` на хосте).

Если разговор с контейнером прервался, вернуться в него:

```bash
./sandbox.sh -t samba-manual samba-training
```

(контейнер уже существует — просто переподключится).

## Шаг 1. Установить Samba

```bash
apt-get update
apt-get install -y samba samba-common-bin
```

`samba` — сам сервер (smbd/nmbd), `samba-common-bin` — утилиты вроде
`smbpasswd` и `testparm`.

Проверьте, что встало:

```bash
smbd --version
```

## Шаг 2. Создать папку для шары

Будем "шарить" существующий `/workspace` (то, что на хосте лежит в
`./workspace`) — так изменения сразу видно с обеих сторон:

```bash
mkdir -p /workspace
chmod 0775 /workspace
```

Если хотите потренироваться на отдельной папке — можно и так:

```bash
mkdir -p /srv/samba/share
chmod 0775 /srv/samba/share
```

## Шаг 3. Сделать резервную копию конфига

Перед правкой всегда полезно сохранить оригинал:

```bash
cp /etc/samba/smb.conf /etc/samba/smb.conf.orig
```

## Шаг 4. Добавить секцию шары в smb.conf

Откройте конфиг редактором:

```bash
nano /etc/samba/smb.conf
```

В конце файла добавьте секцию (замените путь, если шарите свою папку):

```ini
[workspace]
   path = /workspace
   browseable = yes
   writable = yes
   guest ok = no
   valid users = trainee
   create mask = 0664
   directory mask = 0775
```

Разбор параметров:

- `browseable` — видна ли шара в списке при подключении без указания имени.
- `writable` — разрешена ли запись (иначе шара read-only).
- `guest ok = no` — анонимный доступ запрещён, нужен логин/пароль.
- `create mask`/`directory mask` — права на создаваемые файлы/папки.

## Шаг 5. Создать пользователя для доступа к шаре

Samba использует отдельную базу паролей поверх системных пользователей
Linux. Сначала нужен сам системный пользователь:

```bash
useradd --no-create-home --shell /usr/sbin/nologin trainee
```

Затем задать ему пароль **в Samba** (не в Linux — passwd тут не подойдёт):

```bash
smbpasswd -a trainee
```

Скрипт дважды спросит пароль — введите любой, например `trainee123`.

## Шаг 6. Проверить конфигурацию

```bash
testparm
```

Если в конфиге ошибка синтаксиса, `testparm` укажет строку. В конце
нажмите Enter, чтобы увидеть итоговый разбор конфига — убедитесь, что
секция `[workspace]` там есть.

## Шаг 7. Запустить Samba

В контейнере нет systemd, поэтому `service smbd start` может не
сработать. Запускаем демоны напрямую, в фоновом режиме:

```bash
smbd -D
nmbd -D
```

(`-D` = daemonize, т.е. уйти в фон самостоятельно).

Проверьте, что порт слушается:

```bash
ss -tlnp | grep 445
```

Вы должны увидеть `smbd`, слушающий `0.0.0.0:445`.

## Шаг 8. Подключиться с хоста

По умолчанию `-s` пробрасывает 445-й порт контейнера на **1445** хоста
(на macOS порт 445 занят системным File Sharing и его нельзя перехватить
сторонним процессом, поэтому используется другой порт).

- **macOS**: Finder → `Cmd+K` → адрес `smb://localhost:1445/workspace`
- **Linux**: `smbclient -p 1445 -L localhost -U trainee`
- **Windows** (если хост — Windows): `\\localhost@1445\workspace` в
  проводнике, либо `net use Z: \\localhost@1445\workspace /user:trainee`

Логин — `trainee`, пароль — тот, что задали в шаге 5.

## Шаг 9. Проверить изнутри контейнера (без второго компьютера)

Если нет отдельной машины под рукой, подключиться можно и из соседнего
терминала того же контейнера:

```bash
smbclient //localhost/workspace -U trainee
```

## Диагностика

- Логи Samba: `/var/log/samba/log.smbd` и `/var/log/samba/log.nmbd`.
- "`Connection refused`" при подключении — демоны не запущены, см. Шаг 7.
- "`Access denied`" — пользователь не создан или неверный пароль (Шаг 5),
  либо не совпадает `valid users` в конфиге.
- Порт не проброшен наружу — проверьте, что контейнер запускали с `-s`
  (см. Шаг 0); опции применяются только при **создании** контейнера, для
  контейнера, который уже существует, нужно сначала `./sandbox.sh rm
  samba-training` и создать заново.
